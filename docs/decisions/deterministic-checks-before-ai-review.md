# Deterministic Checks Before AI Review

## Status

Adopt.

## Context

The repository uses AI instructions and Agent Skills to review Kubernetes, Helm,
Flux, security, recovery, and operational changes. The first review skill mixed
three different concerns in Markdown:

- deterministic checks that can be decided from repository state
- conditions that code can detect but that still require contextual judgment
- architectural and operational trade-offs that require interpretation

Encoding deterministic checks only as prompts makes their execution dependent on
skill activation, context loading, model behavior, and wording. It also makes the
checks harder to test, reproduce, and enforce in CI.

The repository already prefers executable validation through `make ci`, Helm
rendering, Kustomize builds, Gitleaks, actionlint, and repository-specific shell
checks. AI-assisted review should build on that evidence rather than duplicate or
replace it.

## Decision

Implement every conclusively decidable repository rule as code, configuration,
schema, policy, scanner, or test. Prompts and skills may require those checks to
run and may interpret their results, but they must not be the only enforcement
mechanism for deterministic rules.

Use the following boundary:

- **Deterministic:** code produces a pass, fail, warning, or skipped result with
  evidence. Examples include mutable image tags, unsafe GitHub permissions,
  plaintext Kubernetes Secrets, missing references, failed rendering, and
  sensitive resource-name changes.
- **Detectable but contextual:** code reports the condition and marks it as
  requiring judgment. Examples include PVC, Secret, ingress host, or bootstrap
  changes that may be safe only with an adequate migration and rollback plan.
- **Semantic:** the AI reviews architecture suitability, complexity, operational
  clarity, recovery credibility, trade-offs, prioritization, and residual risk.

Expose deterministic and contextual results through a versioned JSON evidence
format generated by a repository command. The AI review skill consumes that
report as authoritative evidence for the checks it contains, investigates items
marked as requiring judgment, and reports its own conclusions separately.

Test repository-specific analyzers with executable fixtures. Human-readable
Markdown may explain the rules and semantic rubric, but it does not substitute
for executable validation.

## Consequences

- Review instructions become shorter and focus on semantic reasoning.
- CI gains reproducible evidence that does not depend on an AI model or API.
- Repository-specific checks require maintained code, schemas, and fixtures.
- Some checks will remain warnings because code can detect a condition without
  deciding whether the accompanying migration or trade-off is acceptable.
- AI behavior evaluation remains useful for prompt-injection resistance,
  prioritization, factual discipline, and the quality of architectural judgment.
- New review rules must be classified as deterministic, contextual, or semantic
  before implementation. Deterministic rules added only to prompts violate this
  decision.
