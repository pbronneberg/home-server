# Glossary format

Reuse the repository's existing glossary location; create a small context document
only when a resolved domain term needs one. Start with context name and a short
purpose. For each term write its canonical name, a one- or two-sentence definition,
and alternatives to avoid if ambiguous. Group only when useful.
Do not include general programming vocabulary, implementation plans, or open
questions. If distinct contexts already exist, follow their existing map rather
than inventing a new global one.
